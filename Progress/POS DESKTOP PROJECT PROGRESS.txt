POS DESKTOP PROJECT PROGRESS
Last Updated: 2026-06-14

1. Current Status
- Desktop POS application built with Python + PyQt6.
- Supabase is the cloud source of truth for auth, store users, registers, products, product images, sales, inventory, realtime updates, and admin edge functions.
- SQLite remains the local runtime cache/offline store at `%LOCALAPPDATA%\RetailPOS\pos.db`.
- App starts from `main.py`, restores a remembered Supabase/local session when possible, then opens `PosMainWindow`.
- `app_paths.py` centralizes `.env` lookup, runtime DB path, and cache path.
- Main UI uses a QStackedWidget shell with sidebar navigation based on role permissions.
- Current major areas:
  + Login/register store owner, session persistence, logout.
  + POS Terminal, checkout, split payment, receipt preview.
  + Product Management with modal add/edit, barcode handling, image upload/cache, label printing, sync status, retry.
  + Admin: users, registers, reports, audit logs, settings.
  + Background sync, realtime dirty-event sync, and network/offline notifications.
  + Runtime light/dark theme toggle.

2. Recently Completed / Current Changes
- Moved the project from local-only POS toward Supabase-first operation.
- Added `cloud/` helpers:
  + `cloud/supabase_client.py` loads `.env` and creates Supabase clients.
  + `cloud/auth.py` handles login, register store owner, profile fetch, session restore, admin edge functions.
  + `cloud/products.py` handles product CRUD, product barcode sync, Storage upload/download, inventory adjustments.
  + `cloud/inventory.py` handles `checkout_sale`, recent sales, sale items/payments, and registers.
- Added store-aware local schema fields such as `store_id`, `cloud_id`, `sync_status`, `sync_error`, `last_synced_at`, and `deleted_at`.
- Added cloud profile caching into local users table.
- Added Supabase session tokens to the remembered session flow.
- Added store registration UI for first owner account.
- Product Management now uses cloud-required save/delete paths for cloud stores.
- Product table shows sync state and supports retry when sync is pending or failed.
- Product image flow uploads local images to Supabase Storage and caches downloaded images locally.
- Checkout now prefers Supabase `checkout_sale` RPC so sale, payments, and stock update together.
- Offline checkout is limited to Admin users and saved locally as `pending_offline` for later sync.
- Added pending product and sale retry helpers.
- Added background sync timer and realtime worker.
- Added network status notifications.
- Added light/dark theme mode helpers and runtime toggle.
- Updated build flow for PyInstaller + Inno Setup packaging.

4. Runtime Data Model
- Supabase is the main backend for production/cloud stores.
- SQLite is local runtime cache/offline support and must not be packaged.
- Default DB path:
  + `%LOCALAPPDATA%\RetailPOS\pos.db`
- Optional dev override:
  + `POS_DB_PATH=...`
- Product images:
  + source: Supabase Storage bucket `product-images`
  + local cache: `%LOCALAPPDATA%\RetailPOS\cache`
- `.env` lookup:
  + folder beside installed exe
  + project root during development

5. Database And Sync
- Important local tables include:
  + stores
  + roles
  + users
  + registers
  + cash_shifts
  + cash_movements
  + audit_logs
  + settings
  + products
  + product_barcodes
  + sales
  + sale_items
  + sale_payments
  + sync_queue
- Product sync:
  + local changes use `save_product_cloud_required()` for cloud stores.
  + pending/failed products can retry.
  + cloud pull updates local cache and marks missing cloud products inactive.
- Sale sync:
  + normal cloud checkout calls Supabase RPC `checkout_sale`.
  + local sale is stored as `synced` after cloud success.
  + Admin offline checkout stores sale as `pending_offline`.
  + retry pushes pending sale to cloud later.
- Background sync:
  + retries pending products/sales
  + pulls products
  + pulls recent sales
  + refreshes store users/registers
- Realtime sync:
  + realtime events mark product/sale data dirty
  + main window queues a targeted sync

10. Build And Installer
- Setup:
  + `.\setup.ps1`
- Run source:
  + `.\.venv\Scripts\python.exe main.py`
- Build EXE folder:
  + `.\build_exe.ps1`
- Build one-file EXE:
  + `.\build_exe.ps1 -OneFile`
- Build installer:
  + `.\build_installer.ps1`
- Installer output:
  + `installer\Output\RetailPOSSetup.exe`
- Installer destination:
  + `%LOCALAPPDATA%\Programs\RetailPOS`
- Build script bundles only required UI assets, not `assets\products`.
- Installer includes current `.env`; use only `SUPABASE_ANON_KEY`, never service-role keys.
