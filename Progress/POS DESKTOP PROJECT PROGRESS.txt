POS DESKTOP PROJECT PROGRESS
Last Updated: 2026-05-13

1. Current Status
- The project is a desktop POS application built with Python + PyQt6.
- The app uses one main PosMainWindow and switches content with QStackedWidget.
- The left sidebar navigates to POS Terminal, Product Management, dashboards, and admin pages based on permissions.
- SQLite is used through Python's built-in sqlite3 module.
- The runtime database file is pos.db in the project root.
- POS Terminal reads products and saves sales into sales, sale_items, and sale_payments.
- Product Management manages products.
- Admin pages currently include dashboard, user management, register management, reports, audit logs, and settings.
- Global synchronization is now implemented with pyqtSignal so pages can reload after database changes.

4. Global Synchronization
- PosMainWindow exposes:
  app_data_changed = pyqtSignal()

- Data-writing child pages expose:
  + ProductManagementWindow.data_changed
  + UserManagementWindow.data_changed
  + RegisterManagementWindow.data_changed
  + SettingsWindow.data_changed

- Child page flow:
  page.data_changed -> PosMainWindow.notify_app_data_changed() -> app_data_changed.emit()

- PosMainWindow.connect_global_refresh() connects app_data_changed to every page reload handler it can discover.

- Reload handler discovery order:
  + reload_data
  + load_dashboard_data
  + load_products
  + load_users
  + load_registers
  + load_settings
  + load_report
  + load_logs

- Shift+F5:
  + Pressing Shift+F5 calls notify_app_data_changed().
  + Connected pages reload data without restarting the app.

5. Database
- database/db.py creates/migrates required tables in init_db().
- Main tables:
  + products
  + sales
  + sale_items
  + sale_payments
  + sync_queue
- products includes extended fields such as sku, stock_qty, active, updated_at.
- sales includes user_id, register_id, shift_id, total_amount, payment_method, tendered_amount, change_amount, status, created_at.
- sale_items includes product_id, barcode, name, qty, price, subtotal.
- sale_payments stores payment method rows for each sale.
- sync_queue is prepared for future offline/sync work.

6. POS Terminal
- Layout has three zones:
  + Left sidebar.
  + Center product grid.
  + Right cart, totals, and action buttons.
- Product grid:
  + Search/scan bar at top.
  + Product cards show image placeholder, product name, barcode, and price.
  + Clicking a product card adds it to cart.
  + Pressing Enter in search finds by barcode/name.
- Cart:
  + Columns: Name, Qty, Price, Total, X.
  + Qty can be edited with double-click.
  + Qty <= 0 removes the item.
  + Red X removes an item.
  + Vertical scrollbar is always visible for many items.
  + Table scrolls to bottom after adding items.
- Totals:
  + Subtotal
  + Discount
  + Grand Total
- Actions:
  + Pay
  + Split Payment
  + Cancel

7. Payment
- Pay:
  + Opens Payment QDialog.
  + Left side: Total Due, Amount Tendered, Change, Note.
  + Right side: Cash and Bank Transfer radio buttons.
  + Print previews receipt.
  + CONFIRM saves sale, shows Payment Successful, shows Receipt Preview, clears cart.
- Split Payment:
  + Opens Split Payment QDialog.
  + Inputs: Cash and Card/Transfer.
  + Saves sale with payment_method = Split when paid amount >= Grand Total.
  + Shows Receipt Preview and clears cart.
- Cancel:
  + Confirms void transaction.
  + Clears cart and resets discount/totals if confirmed.
- After successful Pay/Split:
  + notify_app_data_changed() refreshes dashboard/reports.

8. Receipt Preview
- Successful Pay or Split creates text receipt and displays it in QDialog.
- Receipt includes:
  + MY POS SHOP
  + Date/time
  + Payment method
  + Items: name, Qty, Price, Amount
  + Total
  + Tendered
  + Change
  + Thank-you line
- Receipt uses read-only QTextEdit with Consolas font.
- Receipt is not exported to receipt.txt yet.

9. Product Management
- File: product_management/product_management_window.py.
- QWidget page inside QStackedWidget.
- Form uses QFormLayout.
- Real-time search uses textChanged.
- Table columns:
  + No.
  + Barcode
  + Product Name
  + Price
  + Category
  + Requires Weight
- No. is display sequence, not database id.
- Real id is stored in UserRole.
- Add/Update/Delete product reloads table and emits data_changed.

13. Developer Notes
- Avoid raw SQL inside UI files when possible. Add database functions in database/db.py.
- If a page writes to DB, add data_changed signal and emit it after save/delete/update.
- If a page needs refresh support, add reload_data() so MainWindow can discover it.
- For POS changes, edit pos_terminal/pos_window.py.
- For Product Management changes, edit product_management/product_management_window.py.
- For database/schema/helper changes, edit database/db.py.
- UI text is currently English by app requirement.
- pos.db is runtime data and may differ between machines.
- .venv and __pycache__ are generated folders, not source code.
