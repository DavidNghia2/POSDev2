POS DESKTOP PROJECT PROGRESS
Last Updated: 2026-05-16

1. Current Status
- Desktop POS application built with Python + PyQt6.
- One main PosMainWindow with QStackedWidget-based navigation.
- Left sidebar exposes dashboards, POS Terminal, Product Management, and admin pages according to permissions.
- Runtime database: SQLite file pos.db.
- Current major areas:
  + Login, session persistence, logout.
  + POS Terminal, payment, receipt preview.
  + Product Management.
  + Admin: users, registers, reports, audit logs, settings.
- Shared refresh flow is handled through app_data_changed.

2. Recently Completed Changes
- Old: sold barcodes remained in the system.
  New: sold barcodes are removed from Product Management and the database.
  Changed: remove scanned barcode after a successful sale and promote the next remaining barcode to primary when needed.

- Old: already-sold barcodes could be scanned again.
  New: unavailable/out-of-stock barcodes are blocked immediately.
  Changed: validation added on scan, before payment, and again inside the database sale transaction.

- Old: multiple barcodes for one product could be merged incorrectly in the cart.
  New: cart rows distinguish scanned barcodes.
  Changed: cart logic now tracks barcode-level sale lines.

- Old: Shift+F5 refreshed silently.
  New: reset shows visible success feedback.
  Changed: added reset toast animation and status-bar message.

- Old: closing the app required a new login next time.
  New: session can persist across app restarts.
  Changed: added stored session recovery using the existing “Keep me logged in” toggle.

- Old: no logout action existed.
  New: sidebar includes Logout.
  Changed: added logout icon/button, session clearing, and return-to-login flow.

- Old: receipt preview could appear before payment fully completed.
  New: receipt is created/displayed only after successful payment completion.
  Changed: payment flow now waits for accepted dialog result before finalizing and showing receipt.

- Old: Product Management used split-screen form + table.
  New: main page is list-focused and Add/Edit use modal dialogs.
  Changed: removed the left Product Details panel and added reusable ProductDialog.

- Old: update/delete depended on shared form state and current selection.
  New: each table row has its own Edit/Delete actions.
  Changed: row action buttons were added; modal edit pre-fills old data; table reloads after save/delete.

3. Main Files
- main.py
  Main entry point; initializes auth DB, restores session when available, launches PosMainWindow.
- pos_terminal.py
  Compatibility wrapper for the legacy command.
- login/login_window.py
  Login, auth helpers, session persistence, cash-shift helpers.
- database/db.py
  Shared database helpers for products, barcodes, sales, stock availability, sale validation, sold-barcode removal.
- pos_terminal/pos_window.py
  Main window, sidebar, cart, payment, receipt preview, reset toast, logout.
- product_management/product_management_window.py
  Product list page plus ProductDialog for Add/Edit.
- admin/*
  Dashboard, users, registers, reports, audit logs, settings.
- ui/icon_manager.py
  Centralized icon system.

4. Global Refresh Flow
- PosMainWindow exposes app_data_changed = pyqtSignal().
- Child pages emit data_changed after database writes.
- Flow:
  page.data_changed -> notify_app_data_changed() -> app_data_changed.emit()
- Reload discovery order:
  + reload_data
  + load_dashboard_data
  + load_products
  + load_users
  + load_registers
  + load_settings
  + load_report
  + load_logs
- Shift+F5 now reloads data and shows visible reset feedback.

5. Database
- Main tables:
  + products
  + product_barcodes
  + sales
  + sale_items
  + sale_payments
  + sync_queue
- products includes barcode, sku, stock_qty, active, updated_at, image_path.
- product_barcodes supports multiple barcodes per product and primary barcode state.
- Added helper logic:
  + get_available_stock()
  + is_barcode_available()
  + was_barcode_sold()
  + ensure_sale_items_available()
  + remove_sold_barcodes()
- Current app behavior treats remaining barcodes as practical sellable inventory; stock_qty exists in schema but still needs a full Inventory UI.

6. POS Terminal
- Layout:
  + left sidebar
  + center product grid
  + right cart/totals/actions
- Product grid:
  + barcode/name search
  + product cards with image, name, barcode, price
- Cart:
  + Barcode, Name, Qty, Price, Total, Remove
  + validates availability before payment
  + prevents duplicate sale of the same scanned barcode in one transaction
- Actions:
  + Pay
  + Split Payment
  + Cancel
- Sidebar now includes Logout.

7. Payment and Receipt
- Pay and Split Payment both validate stock before sale creation.
- Receipt preview is shown only after a successful accepted payment dialog.
- Receipt includes method, items, total, tendered, and change.
- Pre-payment receipt preview flow has been removed.

8. Product Management
- Main page now contains only:
  + Search
  + Add Product
  + product table
  + row-level Edit/Delete actions
- Add Product:
  + opens modal ProductDialog
  + save closes modal and reloads table
- Edit Product:
  + opens ProductDialog with prefilled data
  + save closes modal and reloads table
- Modal still supports:
  + image selection
  + multiple barcodes
  + primary/linked barcode display
  + duplicate-barcode validation

9. Login and Session
- “Keep me logged in” now persists the user session.
- Restarting the app can restore the last user automatically.
- Logout clears persisted session and returns to login.

10. How To Run
- Setup:
  .\setup.ps1
- Run app:
  .\.venv\Scripts\python.exe main.py
- Legacy command:
  .\.venv\Scripts\python.exe pos_terminal.py
